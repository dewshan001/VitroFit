# Diet plan agent: Agentic AI evaluation report

Snapshot of the golden-case evaluation in `BackendAPI/DietPlanService/tests/evaluation`. It is regenerated by every test run
(`pytest -m evaluation` writes `reports/evaluation_report.md`); CI attaches it to the job summary.

## How it was evaluated

- **Golden cases.** 20 cases, each a complete scenario (a user, what the model says, what a reviewer decides). A case is run through the real
  API, coordinator, validator and database. Only the outside world is scripted: the model's replies and the clock's time budget.
- **Rule-based checks only.** Every check is an assertion on stored data or on an HTTP status (for example "the validator verdicts were revise,
  then pass", "no plan was saved", "the model received zero prompts"). No LLM is used as a judge.
- **The ten criteria in the assignment** (planning, delegation, tool selection, structured outputs, deterministic validation, business rules,
  approval enforcement, prompt-injection resistance, failure recovery, safe failure) each have at least one case. A test fails if a criterion loses
  all its cases.
- **The checks can fail.** `python tests/evaluation/mutation_check.py` injects 25 deliberate faults into the code one at a time (approval gate
  removed, injection guard disabled, tool allow-list always true, plan narrowing ignored, output-safety check removed, restriction check removed,
  start-up recovery turned off, concurrency cap ignored, audit mirror removed, service key not checked, and more) and runs the whole test suite
  (unit, integration and these cases) against each. The first run caught 21 of the 25; tests were added for the other four (a race between two reviewers, the
  server-recomputed targets on the legacy save path, the no-retry-when-the-generator-cannot-help rule, and the error message of a second decision)
  until the suite caught all 25.

## What this does not show

- It does not measure how good a **real** model's meal plans are (taste, variety, realism of portions). The model is scripted, so these results
  prove that the control flow and the safeguards behave as designed whatever the model says, not that a real model says good things.
- Regex-based injection detection cannot catch every phrasing or language; the cases cover the patterns the guard targets, including obfuscations
  (look-alike letters, zero-width characters, text split over lines).
- Real-model latency and failure behaviour of this service have not been measured.

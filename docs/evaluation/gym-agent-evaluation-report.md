# Gym agent: Agentic AI evaluation report

Snapshot of the golden-case evaluation in `BackendAPI/GymAgentService/tests/evaluation`. It is regenerated by every test run
(`pytest -m evaluation` writes `reports/evaluation_report.md`); CI attaches it to the job summary.

## How it was evaluated

- **Golden cases.** 21 cases, each a complete scenario (a gym, what the web returns, what the model says, what humans decide). A case is run
  through the real graph, runner, database store and validator. Only the outside world is scripted: the model's replies, the web results and
  the clock's time budget.
- **Rule-based checks only.** Every check is an assertion on stored data (for example "the validator verdicts were revise, then pass", "no
  verified row exists", "the model received zero prompts"). No LLM is used as a judge.
- **The ten criteria in the assignment** (planning, delegation, tool selection, structured outputs, deterministic validation, business
  rules, approval enforcement, prompt-injection resistance, failure recovery, safe failure) each have at least one case. A test fails if a
  criterion loses all its cases.
- **The cases can fail.** 21 deliberate faults were injected one at a time into the code (planner ignores the website, validator skipped,
  tool allow-list removed, role check removed at each of its two layers, hostile sources not withheld, retries removed, time budget not
  enforced, and more). The golden cases alone caught every one.

## What this does not show

- It does not measure how good a **real** model's answers are. The model is scripted, so these results prove that the control flow and
  the safeguards behave as designed whatever the model says, not that a real model says good things.
- Regex-based injection detection cannot catch every phrasing; the cases cover the patterns the guard targets, including obfuscations.
- The real-model latency and failure behaviour are in `docs/performance/gym-agent-latency.md` (from stored runs).
